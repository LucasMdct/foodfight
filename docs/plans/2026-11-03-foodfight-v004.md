# FoodFight v0.0.4 Implementation Plan

> For agentic workers: use subagent-driven-development or executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

Goal: Incorporate the validated v0.0.3 baseline and ship the v0.0.4 full-screen power, typed Barão dialogue, laughing zombies, larger villain, and staged defeat sequence.

Architecture: Merge the v0.0.3 release tag into feature/v004, then keep the fixed-pool UI-thread engine as the owner of per-frame positions, collisions, power authorization, and terminal freeze. React and Zustand receive discrete events only; GameScreen renders fixed Skia pools and ordinary overlays.

Tech Stack: Expo SDK 56, React Native 0.85, React Native Skia 2.6, Reanimated 4, React Native Worklets, Zustand 5, TypeScript 6, Vitest 5, Fredoka.

## Global Constraints

- Preserve the gameplay invariants: no per-frame values in React or Zustand and no allocation inside the UI-thread frame worklet.
- Use docs/design/project/FoodFight v0.0.4.dc.html as the source of truth for geometry, colours, sizes, and animation timings.
- Keep production and src/engine/combatSimulation.ts aligned on spawn order, coordinates, timings, pool sizes, scoring, and terminal guards.
- Use named constants for every v0.0.4 value.
- Do not add audio playback or v0.0.5/v0.0.6 scope.
- Preserve the unrelated local modification in docs/design/project/support.js; never stage it.
- Update CHANGELOG.md under [Unreleased] for user-visible changes.
